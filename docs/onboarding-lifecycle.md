# Onboarding lifecycle

The event x state table first-run onboarding follows (steps: Welcome, Permissions, Speech, Cleanup, Try it, Names, Storage, then Done), plus the Cleanup page rows (C1 to C4). AGENTS.md asks for one test per row; each test below names its row. Rust tests run with `cd src-tauri && cargo test --lib`.

Kinds: **unit** (a function or a struct driven directly), **integration** (real child processes or a real loopback HTTP server), **real** (the real llama-server and s1-mini; `#[ignore]`, run by hand), **UI** (the onboarding screens; frontend), **app** (only the real app can show it).

## State

- `onboarding_step` (`welcome` .. `done`): the step to resume at, written when the step before it completes (`complete_onboarding_step`). It never moves back, so finishing an earlier step again, or the permission screen a returning user sees, keeps the step reached.
- `onboarding_pending_model`: the speech model the Speech step started downloading; cleared at Done.
- `onboarding_completed` stays for older stores and is true exactly when the step is `done`. Choosing a speech model no longer finishes onboarding.
- Migration (stores without `onboarding_step`): `onboarding_completed: true` or a non-empty `selected_model` means `done`; bindings and cleanup settings stay as they were. Otherwise `welcome`.
- `screen_names` (default on): the Names switch.
- `s1_styling`, `s1_structure`, `s1_context`: s1-mini's control line.
- `early_cleanup` ("Clean while you talk"): one stored switch, on for fresh installs.

## Cleanup on the main key, and the second shortcut (rule C1)

With cleanup on (`post_process_enabled`), the main `transcribe` key (Option+Space) cleans. The second shortcut, stored under its old id `transcribe_with_post_process`, now pastes without cleanup ("Dictate without cleanup") and is registered only while cleanup is on, as before. The update (settings schema 3) keeps every key combination and only relabels the second shortcut. So a user who had cleanup on its own shortcut gets cleanup on Option+Space and raw text on that shortcut's keys; a user with cleanup off sees no change.

## Voce cleanup (s1-mini)

`local_llm.rs`. The model is `superwhisper/s1-mini-GGUF` `s1-mini-q4_k_m.gguf` (Apache 2.0, credited "S1-mini by Superwhisper"), pinned to a commit and checked by sha256, downloaded into its own folder `<data>/cleanup` (never the speech models folder, so speech discovery cannot list it; a copy an older build left in `<data>/models` moves there at launch: a complete file counts only if it passes the download's size and sha256 check, an invalid one is removed, and of two partial downloads the larger is kept) with resume (`model-download-progress`, `model_id` `voce-cleanup-s1-mini`). It runs on llama-server on 127.0.0.1, a free port, with the flags that matched LM Studio on all 126 eval cases: `-c 4096 -ngl 99 --jinja --temp 0 --repeat-penalty 1.1 --chat-template-kwargs '{"enable_thinking":false}'`, the s1 system prompt and the control line built from the settings. The server starts on first use, answers `/health` before use, stops after `model_unload_timeout` of idle time (never during a request), is started again after a crash (two failed starts in a row give up until a test retries), and is killed on exit; a pid file lets the next launch kill one a crashed Voce left behind.

The runtime: `VOCE_LLAMA_SERVER` for development and tests; release builds ship llama-server b12818 and its ten dylibs in `Contents/MacOS` (`scripts/fetch-llama-server.sh`, `src-tauri/tauri.sidecar.conf.json`, signed by the release identity; the workflow runs it from inside the built app).

Early cleanup ("Clean while you talk") works for Voce cleanup too. llama-server continues a final assistant message (the template puts the empty think block before the prefill), but sends the prefilled words back with the continuation, where LM Studio sends only the rest; for Voce cleanup the echoed locked words are cut off, and a reply that does not start with them exactly falls back to a whole cleanup. Measured 2026-11-27 with b12818 and s1-mini, through the real path (offers at 3 words a second, then resolve and the release cleanup), release to cleaned text, two runs (off / on, ms): 71 words 452 / 178 and 582 / 163; 142 words 828 / 166 and 972 / 763; 284 words 1288 / 155 and 2515 / 147; every release took the continuation path. Other model servers were running on the machine, so absolute numbers vary between runs. The test fails if the cleaned text with early cleanup differs from the whole-text cleanup by more than 3% of its words (a duplicated or dropped sentence), or if a release that fell back changed the text. Test: `early_cleanup::tests::real_voce_cleanup_release_latency_with_and_without_early_cleanup` (ignored; needs `VOCE_LLAMA_SERVER` and `VOCE_S1_MODEL`).

Call `begin_onboarding_try` again when Try it is shown again. `failed_shortcuts` is the current registration state: a successful `change_binding` clears its entry.

Event `onboarding-practice-text`, payload `{ text: string, cleaned: boolean }`: the text of a dictation started between `begin_onboarding_try` and `end_onboarding_try` (practice mode), sent instead of pasting; nothing reaches the focused app. `cleaned` is true when cleanup ran on it. A dictation cancelled by `end_onboarding_try` sends nothing.

`choice` is `{ kind: "voce_local" }`, `{ kind: "local_server", base_url, model }`, `{ kind: "cloud", provider_id, api_key, model }` or `{ kind: "apple_intelligence" }`. The data folder opens in Finder with the existing `open_app_data_dir`.
